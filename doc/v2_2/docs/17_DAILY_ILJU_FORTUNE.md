# 17. 일주별 오늘의 운세 (Daily Ilju Fortune)

> 원천: 2026-07-23 사용자 제공 PRD(대화 원문 "오늘의 운세 서비스 구성안" + "일주별 오늘의 운세 메뉴 설계안" 1~20장).
> 본 문서가 이 기능의 전체 규격이다. 목록·목차·스키마는 예시가 아니라 규격이며 임의 추가·삭제·재해석을 금지한다(CLAUDE.md 원칙 10).

## 0. 확정 사항 및 불변식

### 0-1. 확정 사항 (2026-07-23 사용자 승인)

1. **PRD 원천** = 본 문서(대화 메시지 본문을 저장한 것). 별도 PRD 파일 없음.
2. **LLM 교정** = 하루 1회 JSONL 배치 호출(60일주 전체를 한 호출로). 자동 재호출 없음.
3. **갱신** = lazy 생성(요청 시 오늘자 없으면 즉시 엔진 생성) + 21:00 KST 익일 선생성 태스크(env 기본 off, 운영에서만 on). 선생성 시각은 2026-08-05 에 23:50 → 21:00 으로 이동했다(0-5 참조).
4. **선택 사주 유지(재로그인)** = account_settings 서버 저장(별도 버그픽스, 유일한 영구 저장).

### 0-2. 휘발성 불변식

> 일주별 오늘의 운세는 KST 당일에만 제공되는 휘발성 콘텐츠다. 과거 운세의 조회·복원·보관 기능을 제공하지 않는다. 서비스는 중복 호출 방지를 위해 오늘과 익일 결과를 TTL 캐시할 수 있으나, 만료 후 자동 폐기하며 운세 본문을 장기 저장하지 않는다.

### 0-3. 최종 불변식

> 오늘의 운세는 규칙 엔진이 계산하고, LLM은 숫자와 사건을 바꾸지 않는다. 결과는 KST 오늘과 익일에 한해 TTL 캐시하며 과거 본문은 저장하지 않는다. 캐시나 LLM이 실패해도 엔진 원문으로 오늘의 서비스를 계속 제공한다.

### 0-4. 검토 반영 구현 규칙 (설계 리뷰 1~3차 확정)

- **사건별 양의 활성도**: 모든 사건(good/caution)은 양의 활성도로 계산. 신호×affinity 동방향=evidence, 역방향=contradiction. `net = max(0, evidence − λ·contradiction)`, `p = 5 + 90·positive_soft_cap(net)`. valence는 슬롯 분류·Top5 집계·헤드라인 분위기 전용(점수 부호 아님).
- **독립 원인 그룹**: DAY_STEM / DAY_BRANCH_RELATION / DAY_HIDDEN_STEMS / MONTH_CONTEXT / YEAR_CONTEXT 5그룹. 그룹당 최강 신호 1개만 독립 원인으로 인정. p≥85는 서로 다른 그룹 ≥2 지지 시에만. p≤10은 강한 contradiction 존재 시에만(없으면 11 상향).
- **관계 세분화**: 육합 / 반합(삼합 2지, 저가중) / 삼합 완성(월지·세운지지가 제3지 채울 때만) / 충 / 형(자형·子卯형·寅巳申·丑戌未 각각 성립 조건 분리, 삼형 2지=부분 가중) / 파 / 해.
- **Top5**: `domain_score = max(good) + 0.3·second(good) − 0.5·max(caution)` (사건 개수 비의존, 빈 후보=0). 동점은 결정론 seed.
  - **연애 Top5 정합(v1.6·beta)**: 연애 도메인은 `domain_score` 정렬 앞에 '오늘의 연애' good 신호 게이트(대표 good 사건 `supporting_groups≥3`, love_line과 동일 판정) 통과 일주를 우선 배치한다. good love_line 이 뜨는데 동반 caution 감점으로 Top5 밖으로 밀리는 불일치를 제거하기 위함(공식·타 도메인 Top5·로또 순위 불변). caution 우세(good-line 아님) 일주는 우선 대상이 아니다.
- **로또**: 적격 = 금전 순위 ≤10 && 공돈 사건 p≥85 && 손실 신호 약함. 당일 최대 3개 일주, 일주별 date-ordinal 슬롯 규칙으로 주 1회 이하(이력 저장 없이 날짜 산술).
- **반복 방지**: 영구 usage 원장 없음. ①날짜 기반 결정론 순환(`seed = hash(date|ilju|event_key|content_version)` permutation) ②당일 60건 내부 중복 감사(완전 중복·시작 구문 집중·장소 과다·로또 최대 3건 — 감지 시 seed salt 재선택).
- **저장** = Redis TTL 캐시만(보드 단위 원자 교체, TTL=운세 날짜 익일 03:00 KST). PostgreSQL 운세 테이블 없음. API는 오늘만 제공(과거·history·archive 금지).
  - 이 캐시는 **"이미 생성했다"는 유일한 기록**이기도 하다. 재생성·재교정을 막는 멱등이 전적으로 여기 걸려 있으므로 컨테이너에 명명 볼륨 + AOF 를 둔다(`saju-v2-redisdata`, `--appendonly yes`, 2026-08-06). 볼륨이 없던 동안 recreate 마다 기록이 사라져 교정 호출의 40%(25회 중 10회)가 같은 날짜 재생성이었다. AOF 가 필요한 이유는 기본 RDB 조건(`3600 1`)이 21시 생성 직후 1시간을 비워 두기 때문이다 — 막으려는 창이 정확히 거기다. TTL 은 그대로라 과거 본문은 여전히 남지 않는다 — 위 휘발성 불변식과 충돌하지 않는다.
- **LLM 교정**: 전용 토큰 정책(감사 CallLimit / 공급자 GenerationPolicy / 사전 BatchEnvelopePolicy 분리). 확률 숫자 미전달, JSONL 줄 단위 검증(키·순서·장소·로또 유무 불변, 신규 숫자·과장·확정 표현·명리 용어 금지), 검증 후 보드 통째 원자 교체. 부분 채택은 최후 방어. finish_reason·토큰 사용량은 기존 LLM usage 로깅에 감사.
- **캐시 헤더**: `Cache-Control: public, max-age=<KST 다음 자정까지>, must-revalidate` (stale-while-revalidate 금지 — 자정 후 어제 운세 노출 방지). 표시 날짜·요일은 API 응답 값 사용(클라이언트 재계산 금지).

### 0-5. 게시 기준일 (2026-08-05 사용자 확정)

스레드 업로드용 텍스트 파일(`오늘의운세.txt`)과 **사용자 API 노출**은 기준일이 서로 다르다.

| | 기준일 | 경계 |
|---|---|---|
| 사용자 API (`/api/v2/daily-fortune/*`) | KST 오늘 | **00:00** (변경 없음) |
| 스레드 export 파일 | 게시 기준일 | **21:00** (`THREADS_PUBLISH_HOUR`) |

즉 13일 21:00 에 14일 보드를 선생성·교정하고 파일까지 14일자로 교체하지만, 사용자는 14일 00:00 부터 14일 운세를 본다. 21~24시 사이 파일 내용은 **내일 것**이며 최상단 날짜 헤더로 구분한다.

- 게시 기준일은 `daily_fortune_export.threads_publish_date(now)` 하나가 정의한다. 어느 순간에도 export 가드를 통과하는 날짜는 **정확히 하나**다 — 21시 이후에는 익일 보드만 통과하고 당일 보드는 막힌다(21~24시 lazy 재생성이 게시분을 되돌리지 못한다).
- 이는 가드 완화가 아니라 **경계 이동**이다. 임의 날짜 보드가 파일을 덮는 사고(2026-08-01: 토요일에 일요일 운세 게시)의 방어는 그대로 유지된다.
- 00:05 에 같은 보드로 export 를 한 번 더 부른다 — 21시 쓰기가 실패했고 재기동도 없었던 경우를 위한 멱등 재확인이다.
- 기동 보충 대상은 **게시 기준일 하나**다(2026-08-06 개정). 21시 전이면 곧 오늘이고, 21시 이후면 익일만 보충한다. 당일 보드가 캐시에 없어도 기동 시점에 채우지 않는다 — lazy 경로가 엔진 생성으로 즉시 응답하고, 교정은 요청이 있을 때만 `maybe_schedule_polish` 가 1회 낸다.
  - 종전에는 당일과 익일을 모두 보충해 21시 이후 재기동이 교정을 최대 2회 냈다. 당일 몫은 전날 21시에 이미 만들어 내보낸 것의 재생성이고 남은 수명도 3시간 미만이라 값이 없다.

## 1. 서비스 구성안 (UI/UX 규격)

### 1-1. 메인화면

- 무료 영역 최상단에 가로라인 전체 사용 카드.
- 비로그인(사주 미등록) 표시: 타이틀 "일주별 오늘의 운세" / 오늘 날짜(요일) / [로그인] 또는 [만세력에서 사주등록] 버튼 / [일주전체보기] 버튼.
- 로그인 또는 게스트 일주 등록 시: 타이틀 / 오늘 날짜(요일) / 해당 일주에 대한 운세 / [일주전체보기] 버튼.
- 필요 수정항목(동반): 이전에 선택한 사주가 재로그인 시 유지될 것(서버 저장).

### 1-2. 일주별 오늘의 운세 페이지 (/daily)

- [일주전체보기] 버튼으로 이동. 햄버거 메뉴 표기 = "일주별 오늘의 운세".
- 상단: 오늘 날짜 + 금전·연애·좋은소식 3분야에 대해 운 좋은 일주 Top5.
- 본문: 일간(10천간)별 탭 메뉴 → 탭당 6개 일주 운세 리스팅.

### 1-3. 기능 구현 원칙

1. 기본 내용은 엔진이 작성한다.
2. 필요시 LLM 1회 호출로 전체 문장을 교정한다(노출 규정 준수 필수). 교정 프롬프트에는 문장 결 규칙(주어·목적어 생략, 문장 길이 변주, 행동·결론 전치, 상투구 회피 — `PROMPT_REVISION=2026-09-01.prose` — `PROMPT_VERSION`은 content_version 구성 요소라 문구 개정만으로 올리지 않는다)을 두되, 의미·강도·장소·로또 유무 불변(규칙 1)이 항상 우선한다.
   - 스레드 업로드 파일(`오늘의운세.txt`)의 행운의 장소는 웹 카드와 동일하게 **장소명만** 적는다(문장형 `place_phrase`는 API 응답 전용, 2026-09-01).
3. 00시 기준 갱신하되, 등록된 오늘의 운세가 없으면 시간과 무관하게 등록한다(최초 1회·서버 이동 등 → lazy 생성).

## 2. 메뉴 개요

### 목적

사용자가 자신의 일주를 선택·저장해 두고 매일 아침 5초 안에 확인하는 가벼운 운세 콘텐츠. 정밀 사주 상담이 아니라 다음에 집중한다: 매일 재방문 이유 / 즉시 이해 / 오늘 일어날 법한 생활 장면 / 바로 실행할 행동 제안 / 공유하고 싶은 문장.

### 핵심 경험

> 오늘은 이런 일이 생길 수 있겠구나. 그러면 이 행동을 한번 해봐야겠다.

아침 방송 운세처럼 밝고 빠르게 판정을 전달한다.

## 3. 콘텐츠 콘셉트

**아침 방송에서 젊은 도사가 툭 던지는 오늘의 한마디.** 근엄한 해설 대신 발랄하고 직설적인 생활 예언.

### 문체 원칙

## 5. 오늘의 한마디 구조

형식상 한 줄이지만 실제 2~3개 짧은 문장. 생성 공식: **오늘 생길 사건 → 바로 할 행동 → 기대할 결과**.

- 좋은 날: "좋은 사건이 생길지도 몰라요! 지금 행동해 보세요. 생각보다 쉽게 풀려요♪"
- 주의가 필요한 날: "문제가 생길 수 있어요. 이 행동만 기억하면 괜찮습니다!"
- 무난한 날도 밋밋하게 쓰지 않는다: "오늘은 새로운 것보다 익숙한 것이 정답! 하던 일을 깔끔하게 마무리하세요."

## 6. 문장 분위기 규칙

- 종결 권장: "~할지도 몰라요!" "~할 예감이에요♥" "~해보세요♪" "오늘이 기회예요." "놓치지 마세요!" "한 박자 천천히!" "지금 움직이면 GOOD!" "생각보다 쉽게 풀려요."

## 13. 행운의 장소

정밀 예측이 아니라 기억·행동 장치. 오늘 가장 강한 사건 영역 × 당일 오행/일주 이미지로 선택. **선정 기준(2026-09-01 데굴님 지시)**: 예약·티켓·회원권·특정 용건 없이 **지나가다 머물러도 이상하지 않은 곳**만 등재한다(부동산 상담소·공방·공연장·사우나 류 제외 → 우체국·버스 정류장·분식집·공원 벤치 등, dict.v1.12). 예: 재물=편의점·은행 근처·마트 계산대 / 업무=회의실 앞자리·조용한 책상·카페 구석자리 / 연락·인연=카페 창가·버스 정류장·베이커리 / 연애=화장품 매장·꽃집·공원 벤치 / 휴식=집 근처 공원·햇빛 드는 창가.

## 21. 베타 풀 배포 (C10 테스터 평가)

### 21-1. 대상 판정

베타 대상은 **배포 환경 전체**다. 계정 플래그·요청 헤더·query parameter·프런트엔드
토글로 legacy/C10 을 고르는 통로는 만들지 않는다 — 사용자마다 다른 풀을 보면
피드백이 무엇을 대상으로 한 것인지 알 수 없고, 헤더는 위조할 수 있다.

| env | 값 | 뜻 |
|---|---|---|
| `DAILY_BETA_POOL_ENABLED` | `true` / `false` | 이 배포가 베타 배포인가 |
| `DAILY_BETA_POOL_VERSION` | `beta-daily-pool.c10.v2` | 활성 풀 |
| `DAILY_BETA_AUDIENCE` | `deployment` | 현재 이 값만 허용 |
| `DAILY_BETA_POOL_EFFECTIVE_FROM` / `_UNTIL` | `2026-07-30` / `2026-08-28` | 공개 창 |
| `DAILY_BETA_EXPECTED_POOL_FP` | **전체 64자 digest** | 지문 고정(버전만 맞고 내용이 다르면 차단) |
| `DAILY_BETA_EXPECTED_BOOTSTRAP_FP` | **전체 64자 digest** | 〃 |

지문은 **접두사가 아니라 전체 digest 완전 일치**를 요구한다. 접두사만 허용하면 우연한
충돌이나 잘못된 파일 교체를 완전히 차단하지 못한다. 64자가 아니면 그 자체로 기동을
막는다(오타·잘라 넣기 방지).

```text
DAILY_BETA_EXPECTED_POOL_FP=f0ce1e0c20c80d892d6a28ac1a286bc2c2cf61fcac0d2209424b6c35f3414f68
DAILY_BETA_EXPECTED_BOOTSTRAP_FP=a499f3424dea1ead18c1f6cbe40f05012e53d9b8d314c025dd6b0951408e53e7
```

### 21-0. 풀 버전 이력

| 버전 | 상태 | 사유 |
|---|---|---|
| `beta-daily-pool.c10.v1` | `WITHDRAWN_BEFORE_DEPLOYMENT` | displacement-loss 기준선 오류(헤드라인 자격 pool 의 1위를 기준으로 삼음). 테스터에게 배포된 적 없음 |
| `beta-daily-pool.c10.v2` | `APPROVED_FOR_BETA_DEPLOYMENT` | 기준선을 good 슬롯 pool 1위로 수정, 의도/실현 대표 분리 |

배포된 pool version 의 내용은 어떤 후속 결과가 나오든 중간 변경하지 않는다. 수정본은
새 버전과 새 지문으로 분리한다(예: `beta-daily-pool.c11.v3`). renderer 계약
(`daily-beta-render.c10.v1`)은 의미 계약이 바뀌지 않는 한 pool 버전과 함께 올릴
필요가 없다.
| `DAILY_BETA_POOL_PATH` | (선택) | snapshot 디렉터리 재지정 |

### 21-2. fail-closed

| 시점 | 사건 | 동작 |
|---|---|---|
| 기동 | preflight 실패(파일 없음·지문 불일치·구조 위반·정책 버전 불일치) | 예외를 억제하지 않는다 → 새 프로세스가 ready 로 진입하지 못하고 기존 프로세스도 교체되지 않는다 |
| 런타임 | snapshot 손상·registry 유실 | 베타 일운 API 만 `503 BETA_POOL_UNAVAILABLE`(`Cache-Control: no-store`). 다른 API 는 영향 없음 |
| 런타임 | 공개 창 밖 날짜 | `BETA_POOL_NOT_YET_EFFECTIVE` / `BETA_POOL_EXPIRED` |
| 런타임 | 렌더 결과가 snapshot 선택과 불일치 | `BETA_POOL_SELECTION_DRIFT` |

**어느 경우에도 legacy 로 조용히 내려가지 않는다.** 내려가면 테스터 일부가 legacy 를
보고 C10 피드백을 준다.

### 21-3. 경로 분리

- 공개 `GET /api/v2/daily-fortune/today[/{ilju}]` — KST 오늘까지만. `allow_future`
  통로가 **존재하지 않는다**(query·헤더 모두).
- 관리자 `GET /api/v2/admin/daily-beta/pool` · `/day/{date}` — `require_admin`,
  미래 날짜 조회와 감사 메타데이터는 여기서만 나간다.

베타 배포에서는 캐시 dep 이 `None` 이고(스냅샷은 Redis 를 쓰지 않는다), 사후 LLM

나중에 바뀐다. 선생성 루프(`SAJU_DAILY_FORTUNE_PREGEN`)도 함께 꺼진다.

### 21-5. 문장 동결 계약

사용자 가시 문장은 다음 조합에 대해 동결된다.

```text
pool fingerprint + commit + renderer contract + content/template/narrative version
```

테스트 기간에 renderer·template·narrative 코드를 **같은 pool version 아래에서 조용히
수정하면 안 된다.** 사건 선택이 같아도 문장이 바뀌면 테스터가 평가하는 제품이 달라진다.

문장 패치가 필요하면:

```text
renderer contract 버전 상승 → 1,800장 전수 재렌더 → render fingerprint 재검증
→ 새 pool version
```

이 계약은 두 겹으로 강제된다.

1. **preflight 코드 드리프트 검사** — 풀에 기록된 `content_version` ·
   `event_selection_contract` · `board_rebalance_version`(값은 `SELECTOR_VERSION`) ·
   `renderer_contract_version` 을 지금 프로세스의 런타임 값과 대조한다. 다르면
   `BETA_POOL_CODE_CONTRACT_DRIFT` 로 기동을 막는다.
2. **golden render fingerprint 회귀** — 공개 창의 3개 날짜(첫날·중간·마지막)에 대해
   `render_result_fingerprint` 를 테스트에 고정한다. 문장이 바뀌면 즉시 실패한다.
   실패했을 때 고정값을 갱신하는 것이 아니라, 새 pool version 으로 올린다.
