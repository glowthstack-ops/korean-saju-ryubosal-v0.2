# 10. 풀이 상품 설계 (총운 / 한해풀이 / 집중 / 대화형)

> **이 문서의 목차·섹션 구성·페르소나 정의는 예시가 아니라 전체 규격이다.**
> Claude Code는 섹션을 임의로 추가·삭제·병합·순서변경하지 않는다. 분량·구성 변경은 사용자 승인 필요.

## 1. 상품 정의

| 상품 | 코드 | 분량 | 생성 방식 | 갱신 |
|---|---|---|---|---|
| 총운 풀이 | `RPT_FULL` | A4 약 20~32장 (고정 16섹션 약 29,500자 + 대운별 페이지 8~10장 — 2026-11-07 개편) | 섹션별 LLM 생성 → 조립 (비동기 작업) | 1회성 + 대운 교체 시 재구매 갱신 |
| 한해풀이 | `RPT_YEAR` | A4 약 11~14장 (본문 약 17,000~22,000자) | 섹션별 LLM 생성 → 조립 | 년도당 1회성 |
| 주제별 집중 풀이 | `RPT_FOCUS` | A4 약 8~9장 (본문 약 12,000~14,000자) | 섹션별 LLM 생성 → 조립 | 주제×기간당 1회성 |
| 대화형 풀이 | `CHAT` | 턴당 응답 | docs/03 오케스트레이터 실시간 | 상시 |

> **분량 캘리브레이션(2026-06-14 사용자 확정 'B').** 각 목차표의 `분량(자)` 컬럼은 **편집 의도값**이며,
> 실제 분량 검사는 `report_plan.calibrate_chars()`가 이를 LLM 실측 밴드로 압축한 값으로 한다. 측정 결과
> gemini-3-flash는 목표 크기와 무관하게 섹션당 ~1,400~1,950자에 수렴(목표 4,500~5,500자 섹션도
> ~1,700~1,950자)하므로, 길게 잡은 목표를 일괄 유지하면 분량 검사(무허용오차)가 항상 실패한다.
> 캘리브레이션 밴드: 짧은 섹션(의도 mid<2,200) → 700~2,200자, 표준·긴 섹션 → 900~2,900자.
> 위 표의 A4 장수는 캘리브레이션 후 실측 기준이다.

세 상품은 **동일한 사전계산 저장소(docs/09)와 Topic Builder를 공유**한다. 보고서는 "대화형 파이프라인을 섹션 수만큼 정해진 순서로 실행해 묶은 것"이며, 별도 분석 로직을 만들지 않는다.

## 2. 공통 생성 파이프라인 (보고서형)

```
ReportSpec (상품/대상/기간/주제/페르소나)
  → SectionPlan[] 생성 (3·4장의 고정 목차 → 섹션별 모듈·기간·분량 확정)
  → 섹션별: Topic Builder 실행 → SectionContextBundle (docs/06 계약 + 분량 목표)
  → 섹션별 LLM 호출 (의존성 없는 섹션은 병렬 허용, 최대 동시 4)
  → 결정적 정합성 검사 (7장) — 실패 섹션만 재생성 (최대 2회)
  → 조립: 표지/목차/페이지 → docx + pdf (스킬 파이프라인 사용)
  → 산출물 저장 + 사용자 알림
```

```typescript
interface ReportSpec {
  productCode: 'RPT_FULL' | 'RPT_FOCUS';
  subjects: SubjectRef[];               // FOCUS는 동반자·궁합 주제 가능
  topic?: Domain | 'compatibility';     // FOCUS 전용
  period: { start: string; end: string };
  personaId: string;                    // 6장
  language: 'ko';
}

interface SectionPlan {
  sectionId: string;                    // 'F-07'
  title: string;
  moduleCalls: { moduleId: string; params: object }[];   // M01~M15
  targetChars: { min: number; max: number };
  dependsOn: string[];                  // 정합성 위해 선행 필요한 섹션 (예: 용신 확정 섹션)
}
```

## 3. RPT_FULL 총운 풀이 — 전체 목차 (규격, 고정 16섹션 + 대운별 페이지 — 2026-11-07 "나 → 대운 흐름 → 인생 그래프" 개편)

아래 `분량(자)`는 편집 의도값(캘리브레이션 전). 캘리브레이션 후 합계 목표 `FULL_TOTAL_TARGET`(고정 섹션 기준)±10%, 대운별 페이지 분량은 별도 가산.

**개편 원칙(2026-11-07 데굴님 확정)**: 총운은 ①원국만으로 "나"를 충분히 설명하고(1부 — 세운·대운·시기 언급 금지) ②대운 전체의 흐름으로 인생이 어떤 형태로 진행되는지 보여 주며(2부 — 출생~90세, 과거 대운 포함) ③그 안의 주요 이벤트 시기(결혼·취업·이직·이사·위기)는 **대운 단위로 입력을 던져 그 10년의 세운에서** 잡는다. **세운은 풀이 내용(섹션)으로 담지 않는다** — 올해 세운·근접 5년 스펙트럼·월별 표 섹션은 총운에서 제외하고, 세운은 대운 페이지 안의 연도 줄과 그래프 마커의 재료로만 쓴다. 인생 그래프(엔진 확정 데이터)는 2부 첫 화면, 글로 된 "인생 흐름 종합"은 대운 페이지 산출을 받아 2부 마지막에 둔다. 도메인 전망 섹션(직업·재물·연애·부모·자녀·건강·이사)은 두지 않고 성향은 1부, 시기는 2부가 담당한다. 섹션 ID는 유지하는 섹션의 번호를 그대로 쓰고(재번호화 금지), 신설은 접미형(F-06b·F-06c·F-14b).

### 3-1. 인생 그래프 (F-14) · 대운별 상세 (F-14-D\*) · 인생 흐름 종합 (F-14b) 규격

- **창**: 출생~90세 (`spec.period` = `lifetimePeriod`). 90세 이후는 "풀이는 90세까지를 기준으로 본다" 한 줄 안내로 종결.
- **데이터**: 전 생애 세운 연 단위 재채점(`lifetime_scan` — 대운표 sewoon 재사용 + 첫 대운 이전 유년 보충, 즉석 재계산 금지). 그래프 데이터는 `saju_engines.life_graph.build_life_graph` → `LifeGraph`(shared_types): 대운 띠(간지·십성·나이·연도·`luck_score`·역할 라벨·지남/현재/예정)·세운 선(해마다 `luck_score`·라벨)·마커.
- **마커 7종(고정, 2026-11-07 개정)**: 인연=new_relationship·relationship_change 길·혼합 방향('만남·관계 형성' 층을 결혼과 따로 — 데굴님 참고 풀이 "27년까지 인연 유리" 대조. 도입 계기였던 미혼 게이트 −12는 2026-11-07 폐지, 인연 층은 독립 마커로 유지. 프로필 상태 분기는 과거 연도에 적용하지 않는다 — 2026-11-08 시점 가드) / 결혼=marriage_signal(방향 무관 — 2026-11-07 결혼운 강의 정정: 엔진 '주의'는 충·형이 아니라 용기신 길흉이므로 마커 `note`에 2축 '인연 창 ○ · 운의 결 길/주의(시기는 열리나 운이 유리하지 않음 → 숙고·궁합 확인)'를 단다) / 취업=job_gain / 이직=career_change / 이사=relocation / 재물 유입=wealth_change 길 방향(데굴님 "돈 들어오는 시기도 표시") / 위기=건강(health_attention)·금전(wealth_change 주의·혼합 방향만). 선별은 **대운 단위**: 연도×종류별 최고 후보 → 품질 게이트 55 → **좌석 보장**(종류별 최고 후보를 우선순위순으로 먼저 배정, 남는 자리는 점수순) → 대운당 최대 9(좌석 종류 9 = 인연·결혼 길·결혼 주의·취업·이직·이사·재물 유입·건강 위기·금전 위기 전부 수용)·같은 종류 최대 2·위기(건강+금전) 합산 최대 2. 결혼은 길·혼합 좌석과 주의 좌석을 따로 보장한다(2026-11-07 실답: 2027년 결혼 66점 길이 2034년 95점 주의에 밀려 사라짐 — 다른 풀이가 짚은 2026~2028 결혼운과 어긋나던 원인). 점수순만으로는 금전 위기 99·96이 결혼 92를 밀어내 "76세에나 결혼"만 남던 실답 교정. 빈 대운은 그대로 둔다(무신호 강제 충원 금지). 위험 엔진(health_safety·finance family, 전 생애 shadow)은 마커를 만들지 않고 같은 해 위기 후보의 우선순위 +10과 '위험 신호 동반' 표기로만 섞는다(2026-11-07 결정 3). **종류별 나이 타당성**(서술 현실성 규칙 — 명리 판정 아님, `KIND_AGE_RANGE`): 결혼 18~70세, 취업 18~70세, 이직 20~70세, 재물 유입 18세+, 이사·위기 전 연령. 미성년(18세 미만)의 이사·금전 위기·재물 유입은 '가족(부모) 단위로 읽을 것' 메모(`note`)를 단다.
- **앞으로의 긍정 창(`LifeGraph.positive_windows`, 2026-11-07)**: 오늘 이후 결혼·취업·이직·재물 유입·이사의 길·혼합 방향 후보(게이트 이상, 나이 규칙 적용)를 **마커 상한과 무관하게** 종류별 연속 연도(공백 2년까지)로 묶는다(시작·끝 연도/나이·최고 연도·점수). `[앞으로의 긍정 창]` 블록으로 F-14 해설·F-14b 종합에 실리고(종류별 가장 가까운 창 3개), 프론트 그래프 아래 "앞으로 기대할 시기" 목록으로 보인다. 지시: 종류마다 가장 가까운 창부터 쓰고 먼 창만 골라 늦은 시기를 강조하지 않는다.
- **배우자성 대운 라벨(`LifeGraphDaewoon.partner_star_daewoon`, 2026-11-07)**: 대운 천간/지지 십성이 성별 기준 배우자성(남=재성·여=관성)이면 대운 줄과 대운 페이지에 "결혼·이성 인연이 본격 거론되는 10년(통설)" 라벨(서술 전용). 개인 이력 '안 일어남' 감점은 후보와 10년 넘게 떨어지면 반감(`personal_calibration.FAILURE_DECAY_YEARS`).
- **시제 표식(`LifeGraph.today_year`, 2026-11-07)**: 마커 줄과 대운 페이지 세운 행의 연도 뒤에 `[지남]/[올해]/[예정]`(`life_graph.when_tag`)을 붙이고, 그래프 블록·현재 대운 서술 계약에 "오늘은 N년 — [지남] 해를 '내년·다가올'로 쓰지 말 것"을 명시한다(실답: 오늘 2026-11인데 2025년 취업 마커를 "내년"으로 쓴 산출). 프론트는 오늘 위치에 점선 세로선을 그린다.
- **누적 운세선(`LifeGraphYear.cumulative`·`LifeGraphDaewoon.trend`, 2026-11-08 데굴님 "이전보다 좋아지는 운인지 알 수 없다 — 주식 차트 같은 거")**: 해마다의 운은 독립 점수라 추세가 안 보이므로, 연도 총점(세운 점수 + 소속 대운 점수)을 출생부터 더한 **누적선**을 점선으로 함께 그린다(주식 차트의 가격선 — 높이=쌓인 수준, 기울기=이전보다 좋아지는지). 대운마다 연 평균·직전 대운 대비 차이·추세 라벨(상승/하강/보합, `TREND_EPS` 0.1; 첫 대운 '시작')을 띠 라벨 옆 ↗↘→ 로 표시하고, `[누적 흐름]` 블록(대운별 평균·대비·추세, 누적 최고/최저 연도, **기준선(누적 0=보통선) 대비 구간·회복 연도·오늘 위치·앞으로의 대운 평균 부호**(`baseline_phase_lines`, 2026-11-08 데굴님 "바닥에서 시작해 지난 대운에 보통선 도달, 앞으로 나아진다는 해석" 대조), 오늘의 생애 분위)으로 F-14 해설에 준다. 프론트는 누적선 축의 0 위치에 '보통선' 점선을 그린다. **설명용 산술이며 명리 판정이 아니다** — 점수·마커·창은 불변, LLM 은 추세 라벨·수치 밖 판단 금지.

```
counselorGender (female/male/neutral) × counselorAgeBand (20s~60s+)
× speech (존대/반말 × 해요체/합쇼체/하게체/반말체 — 유효 조합 제한)
× difficulty (easy/standard/expert)
× userHonorific (프리셋 7종 + custom)
```

본 문서에 남는 불변 규칙 (페르소나보다 우선):
1. 단정 금지 표현 세트, windfall/건강/투자 고지 문구, 미성년 보호 톤(docs/08 G2)은 어떤 페르소나에서도 동일 적용.
2. 점수·날짜·간지·판정 등 **사실 데이터는 페르소나와 무관하게 동일**. 페르소나는 문체만 바꾼다.
3. 보고서(RPT_*)는 생성 시점의 PersonaConfig를 스냅샷으로 고정 — 생성 도중 변경돼도 해당 보고서 내 문체 일관 유지.
4. 일회성 어투 요청("동화처럼")은 PersonaConfig를 바꾸지 않고 OutputStyle.toneOverride로만 처리.

## 7. 정합성 검사 (보고서 — 결정적 검사 전체 목록)

LLM 출력 후 코드로 검증. 실패 시 해당 섹션만 재생성(최대 2회), 2회 실패 시 작업 보류+관리자 알림.

1. 분량: targetChars 범위 내인가
2. 간지 표기: 본문에 등장하는 모든 간지가 입력 calendarContext에 존재하는가 (미제공 간지 등장 = 즉시 실패)
3. 수치 일치: 본문 점수·연도·날짜가 입력 findings/rankedResults와 일치하는가 (정규식 추출 대조)
4. 용신 일관: F-04 확정 용신/기신 표기가 이후 섹션에서 동일한가
5. 금지 표현: prohibited_styles 미출현 (당락 단정, "반드시 ~한다", 로또 당첨 단정, 육친 사망·사별 단정 등). **단정 = 결과를 확정하는 어미만**(2026-10-29, `structural_context.ASSERTION_POLICY`) — "이직이 거론될 수 있다"·"당첨될 수도 있다" 같은 가능성형은 위반이 아니다. 이 검사는 하드 위반(재생성)이라 패턴을 확정 어미·승부 맥락으로 좁혀 둔다(`당첨될 (것|겁니다…)`, `(시험|면접…)에 떨어진다`).
6. 페르소나 준수: docs/11 5-4의 4종 검사 (endings ≥95% / 호칭 단일 / 존대 혼용 없음 / easy 난이도 미해설 용어 0건)
7. 대상 표기: 다중 subject 보고서에서 섹션별 대상 라벨 명시 여부
8. 내부용어 노출: 근거 경로(관계 발동·용기신 품질·복수 가능성 등 스코어링 분류 라벨)·'근거 경로:' 표기가 본문에 그대로 나오면 순화 위반(soft — 재생성 미유발, 기록만). 근거 경로는 **내부 근거**로만 활용하고 사용자 본문엔 일상어로 풀어 녹인다(2026-06-16 개정 — 종전 'evidence path 1개 이상 인용 강제'는 내부용어 누출을 낳아 폐기). 본문 끝 누출 줄은 `_tighten`이 결정적으로 제거.
