# 18. 12신살 방위 활용 계층 + 삼재 (Sinsal Direction & Samjae)

> 원천: 2026-09-20 데굴님 제공 자료(영상 정리 2편 — "사주에 따른 방향 활용 제안", "삼재 계산 추가").
> 본 문서가 이 기능의 전체 규격이다. 목록·표·스키마는 예시가 아니라 규격이며 임의 추가·삭제·재해석을
> 금지한다(CLAUDE.md 원칙 10). 사전 시드는 **감수 없이 적용**(2026-09-20 데굴님 결정, `reviewed: true`).

## 0. 확정 사항 (2026-09-20 데굴님 승인)

1. **명칭 정규화**: 12신살 표준 표기는 `년살(年殺, 도화살)`. 관계 엔진·오늘의 운세 채널의 `연살`을 소스에서
   `년살`로 정규화했다(어댑터가 아니라 소스 정규화).
2. **리포트 노출**: 인생총운(RPT_FULL)·인생연운(RPT_YEAR)은 **별도 섹션**(F-20b·Y-11b, 본인 방 기준 추천 방향).
   확실한 주제가 있는 테마 리포트는 행동 전략 섹션에 주제 목적만 주입(목차 불변).
3. **감수 없이 적용**: 목적×신살 등급·의미 문구는 제공 자료 그대로 시드하고 `reviewed: true`.
4. **livingRoomFacing 사용**: 이익(절대 방위를 '창 쪽/창 등진 쪽' 행동 랜드마크로 번역)이 커서 채택하되 문제 3가지를
   보완해 적용 — ①간방(NE/SE/SW/NW)은 지지 2개 경계라 후보 2개 병기 + 나침반 확인 권고 ②거실 창 기준이라 침실·서재는
   방 창 방향을 따로 확인하라고 고지 ③방향 계산(절대 방위)은 랜드마크와 무관하게 유지(입력 오류가 계산을 오염하지 않음).
   docs/11의 "이사 방위 기준점(residence.region)과 혼용 금지"는 그대로 — 여기서는 M10 기준점으로 쓰지 않는다.
5. **삼재 포함**: 12신살 표의 시간 축 파생값으로 삼재를 계산해 만세력 세운 카드·테마사주·AI 채팅에 반영.
   사건 점수에는 넣지 않는다(맥락 신호). 나침반 하드웨어 연동은 범위 제외(각도 구간 표기는 2026-09-21 채택 — §1-8).

## 1. 원칙

1. **계산은 엔진, LLM은 재서술**(절대원칙 1): 연지→삼합→12방위 신살→목적 등급→활용 전략까지 전부 코드.
2. **방향 자체에 절대 길흉 없음**: `신살 × 행동 → 적합성` 모델. "북쪽은 나쁜 방향" 금지, "북쪽은 겁·재·천 구간이라
   집중·연구·계획과 연결해 해석" 형식.
3. **연지는 만세력 年支**(입춘 기준). 띠(양력 출생연도) 계산 금지 — 1~2월생 경계 오류 차단.
4. **절대 방위 ≠ 상대 신살**: `absolute_direction`(寅卯辰=동, 巳午未=남, 申酉戌=서, 亥子丑=북 고정)과
   `relative_sinsal`(연지 의존)은 별개 필드.
5. **용신 오행 방위와 합산 금지**: `calendar/direction_rules.json`(오행→길방)·`region_direction`(이사 이동 방위)과 서로
   다른 질문. 답변에서는 "오행 보완 방향"과 "활용 방향"으로 분리 병기(지시문 고정). **2026-09-22 데굴님 승인**: 수동 방향 질문(사용자가 직접 방향을 물은 턴 + 방향 지목 후속)에는
   용희기구한 × 정오행 방위(`direction_rules.json` 8방위, `reviewed: false` 초안 그대로) **첨언 블록**을 12신살 블록 뒤에 싣는다
   (`saju_engines/yongsin_direction.py` · `shared_types.sinsal_direction.YongsinDirectionNote` · `LlmInput.yongsin_direction`).
   역할 출처 = 사용자 확정 용신 override(있으면) → `favorability_map`(엔진 도출). 기신·구신 방위는 '피함'이 아니라
   '보완 효과 없음 — 오래 머무는 자리로는 삼가'로 완화(12신살 '주의'와 회피 목록이 둘이 되지 않게). 능동 제안·택일·이사
   (자체 8방위 적합도 보유)·리포트에는 싣지 않는다. 답 구성 계약 ④(docs/19 §6-4)로 한 문단 첨언, 합산·상쇄 금지 지침 고정.
6. **사용 방식 5종 분리**: POSITION(공간 내 위치) / FACE(바라보는 방향) / HEAD(머리 방향) / MOVE(이동) / ENTRANCE(출입구).
   기준점(anchor)은 기본 `USER_POSITION`(본인 방·자리) — 사용자가 말하지 않으면 답에 한 줄 고지.
7. **정성 등급만**: fit(적합)/support(보조)/neutral(중립)/caution(주의). 수치 점수는 자료 근거가 없어 두지 않는다.
8. **각도 = 12지지 30° 등분(2026-09-21 데굴님 승인, 개정)**: 子=정북 중심(345°~15°), 丑 15°~45° … 亥 315°~345°. 지지는 16방위 이름 중 간방 4개를 뺀 12개(정북·북북동·동북동·정동·동남동·남남동·정남·남남서·서남서·정서·서북서·북북서)와 1:1이라 사용자 노출은 '丑 반안살(북북동 15°~45°)'처럼 이름+구간을 병기한다(`shared_types.sinsal_direction.BRANCH_COMPASS` SSOT). 북동·남동·남서·북서는 두 칸 사이의 선(45°·135°·225°·315°) — '경계'·'두 지지에 걸친다' 대신 양쪽 칸 판정과 '…쪽으로 틀면' 권고로 쓴다. 도수는 표기된 구간만 인용(임의 도수 생성 금지), 나침반 앱 각도 확인 권고. (구 규칙 '각도 미정의'는 폐기)
9. **서술 전용(inert)**: 점수·판정·날짜·간지 파이프라인 불변. 페르소나 무관.
10. **기존 `direction_suggestions`(docs/15 E8 삶의 방향 능동 제안)와 다른 계층** — 모듈명 `sinsal_direction`으로 분리.

## 2. 계산 규칙 (SSOT: `saju_shared_types/twelve_sinsal.py`)

삼합국 고지(辰戌丑未) 다음 지지 = 겁살, 이후 子→亥 순으로 재·천·지·년·월·망신·장성·반안·역마·육해·화개.
삼합 3멤버는 같은 표를 공유하며, 관계(상대 12신살)·공간(방위)·시간(삼재) 세 소비처가 이 표 하나를 쓴다.

| 연지 삼합 | 북(亥子丑) | 동(寅卯辰) | 남(巳午未) | 서(申酉戌) |
|---|---|---|---|---|
| 寅午戌 | 겁·재·천 | 지·년·월 | 망·장·반 | 역·육·화 |
| 巳酉丑 | 역·육·화 | 겁·재·천 | 지·년·월 | 망·장·반 |
| 申子辰 | 망·장·반 | 역·육·화 | 겁·재·천 | 지·년·월 |
| 亥卯未 | 지·년·월 | 망·장·반 | 역·육·화 | 겁·재·천 |

12지지 단위 표는 `twelve_sinsal.py` 모듈 독스트링(4행)과 `tests/unit/test_sinsal_direction.py`가 고정한다.

## 3. 사전 `dictionaries/sinsal_direction.json` (스키마 `shared_types/sinsal_direction.py`)

- `groups[4]`: 시련·외압(겁→재→천) / 활동·경험(지→년→월) / 성취·안정(망→장→반) / 변화·수렴(역→육→화).
  각 구간은 **순서 있는 상태 전이**(`sequence_ko`)와 방향판 제목(`quadrant_theme`)을 가진다.
- `sinsals[12]`: 핵심 의미·서비스 적용·기본 사용 방식·활용 전략(8종: activate/focus/face/settle/move/modulate/shield/reflect)·
  행동 문구·주의 문구. 이 의미는 전통 해석의 현대 **활용 해석**이며 별도 모듈로 격리한다.
- `purposes[16]`: 공부·시험 / 연구·기획 / 메이크업·외모 연출 / 소개팅·데이트 / 영업·장사 / SNS·유튜브·브랜딩 / 발표·인지도 /
  리더십·협상 / 숙면 / 여행·이동 / 이사·환경 변화 / 상담·명상 / 자기성찰·정리 / 화해·관계회복 / 새로운 일 시작 / 안정·정착(뒤 3종은 docs/19 §3, 2026-09-21). 각 목적은 파서 어휘(`keywords`)·사용 방식·
  우선 신살·**12신살 전체 등급**(누락 시 스키마 거부)·행동 템플릿·수동 질문 도메인(`domain`)·채팅 능동 트리거(`trigger_domains`)를
  가진다(리포트 섹션→목적은 `report_service` 표가 단일 원천 — 사전에 두지 않는다).
  같은 구간 안에서도 등급이 갈린다(소개팅: 년살 fit / 월살 caution).
- `samjae_stages[3]`: 들삼재(역마살)·눌삼재(육해살)·날삼재(화개살) — 핵심 신호·현대 사건 후보·서술 지침.
- lint(`_lint_sinsal_direction`): 12신살 전수·'연살' 금지·구간 순서·목적 1순위=fit·primary에 caution 금지·삼재 대응.
- 파이프라인: validate → `scripts/build_sinsal_direction_snapshot.py` → `compiled/sinsal_direction_v{VERSION}.json`(현재 1.2.0 — 2026-09-21 등급 합집합·목적 16종·신살 맥락 필드) →
  드리프트 테스트(`test_compiled_snapshot_drift.py`). 런타임은 스냅샷 우선 로드.

## 4. 삼재 (시간 축)

- **정의**: 연지 삼합 기준 세운 지지가 역마살·육해살·화개살에 해당하는 연속 3년. 역마=들삼재(변화의 시작), 육해=눌삼재
  (마찰·적응), 화개=날삼재(수렴·정리). 별도 표 없이 12신살 표에서 파생(`samjae_for`).
- **경계**: 만세력 세운과 동일한 **입춘 기준**(`year_ganzi`). 설날 기준 민속 삼재와 다를 수 있음을 필요 시 한 문장으로만.
- **저장**: `LuckPillar.samjae: SamjaeInfo | None`(세운 전용; 월운·대운은 None). 내부 enum `enter/stay/exit`,
  노출 라벨 들/눌/날. `luck_score`·라벨·사건 점수 **불변** — 부정 신호 포화 방지.
- **노출**: ①만세력 세운 카드 보라색 배지(툴팁에 근거·입춘 기준·"흉운 점수 아님") ②채팅 `[삼재 흐름]` 블록(오늘~+2년 ∪
  질문 창 연도 중 삼재 해만, 없으면 무헤더; 용어교육·피드백·범위외·비교·개운 질문엔 미노출) ③리포트 F-11(오늘~+2년)·
  F-14/테마 5년 종합(예측 창)·Y-04/Y-11b(대상 연도). `[삼재 지침]`: 3단계 변화 과정으로만, 결과 길흉은 다른 신호가 결정,
  공포 조장 금지(`prohibited_styles` "삼재라서 큰일" 유지).

### 4-2. 삼재 품질(복/평/악) — 2026-09-20 데굴님 승인(가중치·임계 = 서비스 캘리브레이션 상수)

- **2축 분리**: stage(들/눌/날)=진행 단계(context), quality(복/평/악)=그 삼재 세운이 원국·대운과 실제로 작용하는 상태.
  띠 lookup으로 복/악을 확정하지 않는다. 엔진 `saju_engines/samjae_quality.py::evaluate_samjae`.
- **합성식**(전부 기존 산출값, 사전 `samjae_quality.weights`): 세운 `luck_score` clamp±1 ×0.45 + 대운 `luck_score` clamp±1 ×0.25
  + 충 성격 주석("기신 충거(정리)" +0.10 / "용신 기반 손상" −0.10) + 십성 균형(세운 천간·지지 십성군이 원국 부족군(<9%) +0.15 /
  과다군(≥35%) −0.15 — E8 임계 재사용) + 사건 방향((유리 점수합−불리 점수합)/전체합 ×0.20, 후보가 있는 경로만)
  + 대운·세운 동조(둘 다 |x|≥0.15 같은 부호면 ±0.10). 충·공망·합 변환·합거 완화는 이미 luck_score에 있어 재감점하지 않는다.
- **판정**: `≥+0.25` 복 / `≤−0.25` 악 / 그 사이 평. **평삼재는 필수 상태**(방향성 없음 — 모든 삼재를 복/악으로 양분하지 않는다).
  복≠대길, 악≠사고 확정(사전 `quality_meaning`, forbidden_framings).
- **강도**(방향과 분리): `0.6·min(1,|세운 luck_score|) + 0.4·min(1, event_trigger/1.5) + 0.2·겹삼재 수` → 약(<0.33)/중(<0.66)/강.
- **겹삼재**(방향이 아니라 강도 축, 실제 판정): `daewoon`=그 해가 속한 대운 지지가 연지 삼합 기준 삼재권(역·육·화 위치) /
  `natal_clash`=삼재 세운 지지가 원국 지지와 충(기존 `relations_to_chart` '충:' 재사용, 민속 '충 겹삼재'). 일지 삼합 기준
  삼재는 연지 삼재와 지지 집합이 서로소라 같은 해에 겹칠 수 없어 정의하지 않는다.
- **도메인 등급**: 그 해 후보를 `EVENT_DOMAIN`으로 묶어 같은 ±0.25 임계로 유리/혼합/주의. 후보가 없는 도메인은 항목 자체를
  내지 않는다("신호 약함" 문구 금지).
- **근거(evidence)**: signal(내부명)·effect·contribution(내부 수치)·note(한글, 기존 엔진 라벨 재사용). 프롬프트·화면엔 note와
  부호만. `event_signal_included`는 **내부 플래그** — LLM 줄·배지 문구에 절대 싣지 않으며 지시문 ⑥이 "데이터/후보 유무 언급
  금지"를 고정한다(2026-09-20 데굴님 지시).
- **표현**: stage×quality 9칸(`stage_quality_phrases`) — 복·악 6칸은 제공 자료 §9 표, 평 3칸은 2026-09-20 승인 초안.
  출력 예: "올해는 눌삼재에 해당하지만 복삼재 성격이 우세하다 …" + 영역별 차이 + 겹삼재는 강도로만.
- **미커버 연도**: 세운 기둥이 없는 해(첫 대운 이전·대운표 밖)는 stage만 판정하고 quality를 비운다('삼재 해 아님' 오판 금지).
- **노출**: 만세력 세운 배지 `들삼재·복`(복 emerald/평 violet/악 rose, 툴팁에 단계×성격·근거; 용희신 보정 뷰에서는 보정 전
  근거와 모순되지 않도록 단계만), 채팅·리포트 `[삼재 흐름]`
  (사건 방향·영역 등급은 후보가 있는 채팅·리포트에서만 합성; 만세력 페이지는 후보 없이 판정).
- **연도 범위 질문**: '2034년부터 2036년까지'는 파서가 2034~2036 스팬으로 잡아(2026-09-20 `_YEAR_SEP_RE` 보정) 삼재 해마다
  단계·성격을 따로 싣는다.
- 사전 버전 1.1.0(스냅샷 `compiled/sinsal_direction_v1.1.0.json`).

## 5. 배선

### 5-1. 채팅 (`context_reducer.build_llm_input` → 동적 suffix)

- **수동**: 파서 `detect_direction_purpose`(공간 단서가 있는 방향 표지 + 사전 keywords 최장 매칭/사용 방식 어휘; 비유
  '공부 방향·방향을 잡다'와 양자택일 '어느 쪽이 좋을까'는 제외) → `IntentJson.direction_purpose/direction_usage_mode`
  (시점 후속 턴에는 물려주지 않음). 배치·시선·머리·출입구 질문은 Q10(REMEDY)으로, 이사·여행(이동)은 기존 이사 방위 경로 유지 + 블록 부가.
  도메인은 목적으로 보정(공부→education, 소개팅→relationship, 영업→wealth, 발표→career, 숙면→health, 이사→relocation).
  **시점 미승계**(conversation 가드, career_field와 동일).
- **능동**: 방향 질문이 아니어도 `detect_purposes_for_intent` — intent 도메인 순서로 사전 `trigger_domains` 매칭, 최대 2목적
  (education→공부, relationship→소개팅, wealth→영업, career→발표·리더십, health→숙면, relocation→이사, EMOTIONAL_SUPPORT→
  상담·명상). general·비교·택일(용신 방위 블록과 중복)·용어교육·피드백·범위외는 무노출. 토큰 초과 시 능동 블록·삼재 블록은
  Tier 0에서 먼저 잘리고 수동 블록은 유지된다.
- **랜드마크**: `profile_engine.living_room_facing_for(subject_id)` → 블록에 창 쪽/창 등진 쪽 병기(간방 모호 표시).
- 블록 `[방위 활용 — 12신살 기준]` + `SINSAL_DIRECTION_INSTRUCTION`. 캐시 프리픽스 불변(대상별 프로필).
- **오행 보완 첨언(2026-09-22)**: 수동 블록 뒤 `[오행 보완 방향 — 용희기구한 기준(첨언…)]` + `YONGSIN_DIRECTION_INSTRUCTION`.
  질문 지목 방향('남쪽은 어때?')은 그 8방위(16방위 중간은 인접 2개)의 오행·역할 줄 병기. 토큰 트림 시 수동 블록과 같이 유지.
- **2026-09-21 개정(docs/19)**: ①수동 방향 질문은 되묻지 않고 `기본 방향(질문 목적) → 목적 전체 한 줄표(상황별 조언 재료) →
  피할 방향(그 목적의 caution 전부, 같은 4방 제한 폐지)` 순으로 싣는다. 목적을 못 잡아도 사용 방식(머리→숙면, 바라보기→공부)으로
  확정하고, 둘 다 없으면 방향판+표만 준다(`IntentJson.direction_question`). ②방향 질문은 승계 도메인 기반 능동 목적을 쓰지 않고,
  직전 되물음(offer)의 '답'으로 링크하지 않는다(실로그: 공부 방향 되물음 뒤 '잘때는 어떤방향'이 제안 수락으로 링크돼 천살이 수면에
  적용). ③등급은 5단계 verdict(적극 활용/잘 맞음/중립/주의(목적 충돌)/강한 회피)로 표시하고 강한 회피는 세운·삼재·영역 중첩으로만
  (docs/19 §4). ④민속 흉방(삼살·대장군·태세·세파·손방)은 별개 층으로 추가 정보 고지(docs/19 §5).
