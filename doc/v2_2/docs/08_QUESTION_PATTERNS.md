> 출처: 이전 버전 실사용 로그 `user_questions_export.csv` — 2,255건 / 353명 (2026-05 ~ 06).
> 목적: **가능한 경우의 수를 모두 기록**해 오케스트레이터·파서 개발 시 누락을 방지한다.

## A. 대상(Subject) 차원 — 13패턴

이전 버전은 n명의 동반자 사주 등록을 지원했고, 사용자는 이를 적극 활용했다. **대상 해석 오류가 가장 치명적인 실패 유형**이다 (실제 로그: "너 내 사주랑 아들사주를 헷갈려서 내 사주로 풀이했는데 다시 체크해봐").

| ID | 패턴 | 실제 예시 | 처리 |
|---|---|---|---|
| A1 | 본인 단독 (기본값) | "재물운 풀이해줘" | subject = self |
| A2 | 등록 동반자 단독 | "엄마의 사주는 어때?", "남편의 재물운은 어때?", "아들 운" | subject = companion(엄마). 본인 사주 미사용 |
| A3 | 본인+동반자 1명 관계 | "남편이랑 내 궁합을 봐줘", "남편과의 사이는 어때?", "자녀들의 사주와 내 사주가 잘 맞는지" | comparison(self, companion). 관계 유형(부부/부모자식/연인/친구/동료) 구분 |
| A4 | 본인+동반자 N명 집단 | "우리 가족 모두", "우리 둘 다 돈 관리나 재물운은 어떤지" | 개별 분석 + 집계(Aggregation) |

| A7 | 다수 미등록 제3자 일괄 비교 | "1998.07.23 여자, 1997.10.16 여자, 1998.08.24 여자 이 3명과 앞서 물어본 2명까지 포함했을 때, 나랑 합이 좋은 사람은 누구야??" | 복수 임시 subject + **이전 턴의 임시 subject 누적 참조** ("앞서 물어본 2명") |

| A9 | 대상 번호/별칭 참조 | "1호 2호 둘다 봐줘 그리고 1호는 금 토가 용신 희신이니까", "우리 딸 1호가" | 동반자 별칭("1호", "신랑", "아가") ↔ 등록 ID 매핑 테이블 |

| A11 | 합산 의사결정 (가구 단위) | "올해 이사를 준비하고 있어. 둘의 사주를 종합해서 언제 이사를 가는게 좋을지", "우리 가족에게 좋은 방 방향" | family aggregation: householder_primary / 균형 / 취약자 우선 규칙 |
| A12 | 익명 일반인·유형 질문 | "1998년 7월생이랑은 올해 하반기에 어떤 운이 들어와?" (생일만, 시각 없음) | 부분 정보 사주(연주/월주만) 처리 + 정밀도 한계 고지 |
| A13 | 생시 미상 | "태어난 시간은 몰라" | 시주 제외 3주 분석 모드 + 신뢰도 하향 고지 |

**파생 규칙**:
- A6/A7의 임시 subject도 Entity Tracking에 등록해 후속 턴("그 여자랑은?")에서 참조 가능해야 한다.
- A5의 실존 공인(정치인) 비교는 E12 정책 참조 — 당락 단정 출력 금지.
- subject가 미성년(아래 G2)이면 표현·도메인 제한 적용.

**파생 규칙**:
- B2/B3는 직전 intent 전체를 상속하고 시점 슬롯만 교체한다. "모레는?"의 parent가 "내일 연애운"이면 도메인(연애)도 상속.
- B4/B5는 **multi-intent 배열**로 파싱한다. 단일 intent 강제 시 절반이 누락된다. 답변도 질문 수만큼 섹션 보장.
- B7의 조건(방위, 특정 상대, 가정 행동)은 constraints로 전달하고, 답변에 조건부임을 명시.
- B8은 시나리오 분기: 조건 성립/불성립 두 갈래를 모두 또는 선택적으로 풀이.
- B9/B10은 Past Validation 피드백 루프(cases.jsonl)로 적재. B10에서 시스템 내부 개선책(CoT/RAG 수정안)을 사용자에게 노출하지 않고, 오류 인정 + 재풀이로 대응.
- B11은 **프롬프트/모델 정보 비공개 정책** 고정 응답. OpenAPI 등 코드 페이스트는 서비스 범위 외 안내.
- B13은 풀이보다 공감 우선 + 도메인 연결(부모운/건강운)은 사용자가 원할 때만. 자해·위기 신호 시 풀이 중단·전문기관 안내(G1).

## E. 경쟁/승부 예측 (winner_prediction) — 별도 정밀 기록

실제 사용 형태 (선거 시즌 집중 발생):

1. **동반자 2인 등록 후 본인 제외 비교**: "나를 제외하고 동반자 두사람의 사주만으로 분석해줘. 기호 1번 ○○○과 기호 2번 ○○○... 둘 중 누가 당선될까?"
2. **3인 이상 다자 경쟁**: "후보자는 1번 ○○○ 2번 ○○○ 6번 ○○○이야" (당선자 예측)
3. **판정일 명시**: "6월 3일이 투표일", "개표가 끝나는 6월 4일", "당선 발표는 그 다음날" — 어느 날짜 기준으로 운을 봐야 하는지 사용자가 인지하고 정정함 ("실제 당선 발표는 6월 4일 새벽이야. 그래도 당락은 동일한거야?")
4. **결과 조건부 후속**: "당선이 되면 운명이 바뀌니까 선거 이후 운까지 같이 봐줘"
5. **합격 경쟁**: "창업오디션", "30년 고입 33년 대입 합격운", "아들의 합격운"
6. **연애 다자 비교**: "이 3명과 앞서 물어본 2명까지 포함했을 때 나랑 합이 좋은 사람은 누구야??" (랭킹 요청)

**처리 정책**:
- 비교 자체는 지원 (당일 운세 강약 + 해당 이벤트 신호 비교 → 상대 우열).
- **당락/승패 단정 출력 금지**. "X 후보의 해당일 운이 상대적으로 강하다" 수준 + 단정 금지 규칙 첨부.
- 실존 공인 대상 예측은 명예/선거 관련 리스크가 있으므로 톤 제한을 templates에 고정. 출생 시각 불명(공인은 대부분 시각 미상) → A13 모드 + 신뢰도 하향 명시.
- 판정 기준일: 사용자가 명시한 날(투표일 vs 개표일) 중 **사건 확정일**을 기본값으로 하되 사용자 지정 우선.
